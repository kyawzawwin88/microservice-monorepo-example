## Summary

Hardens order list pagination for operators: the sales API validates and clamps the `page` query parameter, and the Orders UI keeps page context on refresh and polling while jumping to page 1 only after a successful create.

## Specification

- **Spec**: [spec.md](../spec.md)
- **Plan**: [plan.md](../plan.md)
- **Tasks**: [tasks.md](../tasks.md) (7/7 complete)

Key requirements:
- Paginated `GET /orders` with metadata (`current_page`, `last_page`, `per_page`, `total`)
- 422 for invalid `page` values
- Clamp out-of-range pages to the last valid page
- UI prev/next controls consistent with Invoices/Payments
- Post-create navigation to page 1; refresh/poll stay on current page
